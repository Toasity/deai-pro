# 基于现有性能数据的瓶颈分析计划

## 1. 目标与范围

分析现有 25 条流水线的性能数据，为优化方向选择提供证据：

1. 时间主要消耗在哪些流水线、执行阶段和代码区域？
2. 哪些开销来自重复计算、Python 执行、原生库计算、数据移动或初始化？
3. 哪些优化方向值得优先实验，其潜在收益、风险和证据强度如何？

保留原有约束：

- **仅分析已有数据，不重新运行流水线或 profiler，不实现优化系统。**
- 不修改原流水线、profile、trace、预测文件及现有汇总。
- 区分“已观察事实”“有证据支持的假设”“待实验验证”。
- 不把理论收益上限写成实测加速比。
- 结论限定于当前轨迹，不推广至全部十个轨迹。
- 本计划聚焦优化思路与实验方向，不包含数据审计、指标重算或对账。

现有输入包括 25 份 profile、25 份 trace、100 条分类记录、执行汇总及预测文件。直接使用现有分类统计作为探索性分析入口，以下数值未经本次独立重算：

| 分类 | 现有归因时间 |
|---|---:|
| 模型相关 | 38.71 秒 |
| 初始化 | 25.60 秒 |
| 数据处理 | 9.33 秒 |
| 其他 | 0.93 秒 |

Profile 总耗时约 75.07 秒，与分类合计约有 0.50 秒差额。这些数据不视为无 profiler 的真实基线。

## 2. 性能分析流程

### A. 轨迹、步骤与流水线三级分析

基于现有 CSV 和 profile 中的指标进行描述性汇总：

- 每条流水线耗时及累计贡献。
- 七个步骤的总时间、平均耗时与分类构成。
- 初始化、数据处理和模型相关计算的绝对时间及占比。
- 承担大部分采样耗时的流水线集合。

分类占比采用“分类总时间 ÷ 同一纳入范围的总时间”，不平均各流水线百分比。部分数据必须标注实际分母和覆盖范围。

产出：

- 流水线耗时排名与累计贡献图。
- 按步骤排列的分类耗时堆叠图。
- 步骤与性能类别的耗时热力图。

### B. 代码区域与采样覆盖分析

结合原始 profile、源码和 trace 探索以下代码区域；行号或代码对应关系不明确时，不强行关联：

- 导入与初始化。
- 文件读取和结果写出。
- 特征工程。
- 交叉验证拆分。
- 预处理拟合与转换。
- 模型拟合。
- 预测、融合与评分。

每个区域记录代码位置、归因时间、Python/native/system 构成、内存和复制信息、证据来源及可信度。

新增两项明确规则：

1. **零采样不等于零成本。** 无时间样本的操作标记为“耗时未解析”。若仅 trace 观察到调用，写明“追踪执行中观察到调用；profile 耗时未解析”，不假定两者属于同一执行。不将其作为零收益证据。
2. **区域包含相关 helper 函数。** 显式记录调用行与 helper 行的归属，每条归因记录只计一次。共享 helper 无法可靠拆分时保留合并区域，不任意分配耗时。

重点检查 `apply`、字符串解析、未使用特征、`fit_transform`、`transform`、`fit`、`predict_proba`、重复预处理及重复导入。

产出：热点清单、区域归属表，以及每条流水线的瓶颈结论或“证据不足”说明。

### C. 全轨迹重复计算分析

**在全部 25 条流水线之间发现共享计算，不再局限于同一步或相邻步骤。** 步骤顺序和屏障用于判断结果何时可复用，而非限制候选发现。

核查：

| 候选区域 | 必须比较的条件 |
|---|---|
| 数据读取与特征工程 | 输入依赖、列集合、处理规则和行顺序 |
| 折内预处理 | 训练行、标签依赖、变换器及参数 |
| 模型训练与预测 | 特征、训练折、模型参数、随机种子 |
| 融合与阈值变体 | 上游概率生成逻辑、权重与阈值差异 |
| 未使用特征 | 是否影响后续数据、校验或输出 |

区分：

- **源码等价候选：**源码和依赖支持复用假设。
- **已有产物线索：**预测一致性可作为后续验证的线索，不单独据此认定历史计算可复用。
- **无法确认：**保持候选状态，不宣称已验证复用。

优先检查阈值变体，以及早期单模型在后期融合流水线中的重复训练。

对于源码支持复用假设、且归因时间可解析的重复区域，可用“重复归因时间合计减去保留一次的归因时间”做探索性情景估计，明确假设计算兼容且忽略缓存开销，不视为已核验的收益上限。未解析区域不补零、不虚构精确收益；重叠区域不重复计数。

### D. 内存与并行机会

- 将现有峰值、分配量和复制量作为辅助线索，观察其是否与耗时热点重合；不将未经核验的复制指标作为定量收益依据。
- 按 manifest 的步骤屏障识别独立任务。
- 以各步骤最长流水线耗时之和，估计无限资源、无争用条件下的理想执行时间下界。
- 明确现有顺序采样数据不能证明并行时的资源争用、实际峰值内存或真实加速。

产出：内存风险和调度优化的理论空间，而非实测收益。

## 3. 优化决策与交付物

### 3.1 决策规则

保持原有方向映射：

| 证据模式 | 候选优化 |
|---|---|
| 初始化重复且占比高 | 持久 worker、减少重复导入 |
| 训练或预处理重复 | 跨流水线结果复用 |
| 模型计算占主导且存在独立任务 | 线程配置、折/模型/候选并行 |
| Python 特征处理热点 | 向量化、局部改写 |
| 数据转换与复制同时耗时显著 | 减少转换、优化表示、局部 Polars |
| 稳定且占比大的 Python 区域 | Rust 或专用 kernel |
| 昂贵且规则难覆盖的重复区域 | LLM 辅助改写 |

每项建议包含证据、覆盖范围、潜在收益及估计假设、不可确定部分、实现成本、质量风险和后续最小验证实验。本次不执行这些实验。

使用 Amdahl 定律辅助讨论给定占比假设下的理论空间，但不重复累加重叠机会。证据充分时提出 2–3 个优先方向；不足时提供候选及尚缺证据，不强制排名。

### 3.2 计划交付物

后续执行分析时新增：

- `analyze_bottlenecks.py`：只读取原始输入、生成独立分析输出。
- `docs/performance_analysis.md`：中文分析报告。
- `results/spaceship_titanic_students/bottleneck_analysis/`：汇总表、热点表、共享计算候选表、决策表和图表。

本次仅保存修订计划，不创建分析代码或修改数据。

### 3.3 验收标准

- 覆盖全部 25 条流水线；无法形成结论的部分明确说明。
- 每项结论可追溯到原始记录或代码区域。
- 不混用无法关联的时间与预测结果。
- 零采样标为未解析；helper 样本归属明确且无重复计数。
- 复用发现覆盖非相邻步骤。
- 明确现有汇总未经本次审计和独立重算，不将探索性结果表述为已验证收益。
- 图表与表格一致，不生成单次采样的伪置信区间。
- 优化建议区分理论空间、已有证据和待验证收益。

## 4. 修订摘要

- 删除独立的数据审计与结论准入流程，以及对应的审计清单交付要求。
- 删除指标重算与对账阶段，以及对应的验收要求。
- 直接从轨迹、步骤与流水线三级分析开始，保留代码热点、全轨迹重复计算、内存与并行机会分析。
- 现有数据用于讨论优化候选和设计后续实验；定量估计保留假设与局限，不作为实测加速结论。

### 剩余不确定性

- 已有文件可能缺少足以证明历史输入和执行身份的信息，无法靠只读分析补回。
- 单次采样仍不足以证明耗时稳定性或真实优化加速。
- 部分操作耗时可能无法解析，部分 helper 的时间可能无法可靠拆分。
- 现有分类统计和复制指标未经本次重算，可能存在遗漏或口径偏差。
- 当前证据可能只能支持源码层面的复用候选，不能证明缓存收益或优化后的预测质量。
- 允许最终仅给出有条件的优化建议，而不是确定的瓶颈排名。
