# Notebook 模块计划：Pipeline 内部耗时归因与热点稳定性

## 1. 目标与交付形式

在 `descriptive_statistics.ipynb` 中追加 **Module 2 — Runtime Attribution and Hotspot Stability**。若 notebook 尚未创建，实施时先完成 Module 1，不覆盖其内容。本文件是分析计划，不代表分析已实施。

全部说明、图表和结果解读使用英文；沿用“问题与方法 → 小型代码 cell → 输出 → 结果解释与局限”的结构。每个代码 cell 只处理一个任务，通常为 10–30 行；读取、验证、分类、汇总和绘图分别组织，不隐藏在单个大型函数中。

本模块回答：

- 昂贵 pipeline 的采样热点落在导入、数据读取、特征处理、预处理、训练、预测还是输出？
- 热点主要表现为 Python、native 还是 system 字段贡献？
- 同一阶段或源码行是否在 10 轮中持续成为热点？
- 哪些发现足以支持下一步调查，哪些还需要阶段计时或新的实验？

本轮不实施缓存、并行、模型替换，不重新采集 profiles，不将采样归因当成加速效果或因果证明。跨 pipeline 重复计算识别作为后续模块，不在本模块提前宣称可复用。

## 2. 数据来源、有效性与归因口径

### 2.1 输入与衔接

- 显式配置项目、profiles 和可选 libraries 路径。当前原项目为 `/Users/tue/Documents/10_Projects/deai-pro`，profiles 为 `profiles/spaceship_titanic_students/run_01` 至 `run_10`。
- 使用 manifest 定义 25 个候选、步骤和顺序；使用原始 profile 与对应源码，不依赖旧导出 CSV。
- 复用 Module 1 的路径、有效运行清单和耗时表；缺少前置变量时提示先运行 Module 1，不悄悄读取陈旧结果。
- 全部候选参与概览。详细展示集合为 Module 1 完整轮次中按中位数排序的 Top 5，加上每步中位数耗时最高的候选，去重；并列按 manifest 顺序。没有完整轮次时保留各候选独立分析，不提供全局优先级排名。

### 2.2 字段语义先于汇总

实施时先检查本地 Scalene 序列化/计算源码，记录 `n_cpu_percent_python`、`n_cpu_percent_c`、`n_sys_percent` 的定义、分母和可加性。记录本地版本，并说明本地版本是否能与采集版本核对；无法核对时注明限制。

- 默认呈现 profiler 原始百分比字段，不直接将 `elapsed_time_sec × percent` 表述为阶段实测秒数。
- 字段共用分母且可加时，定义 `reported_share_pct` 为三字段之和；否则分别汇总，并停止合并百分比图。
- 不用 `cpu_samples_list` 长度计算 CPU 占比；不把顶层 `samples` 当成 CPU 样本数，该结构需独立核对，可能记录内存时间序列。
- `functions` 与 `lines` 不相加，避免重复计数；本模块以 `files[*].lines` 为唯一归因记录源。
- 不将 `100 - 已报告占比` 自动解释成 I/O、等待或启动成本，也不强制归一化成 100%。

### 2.3 源码匹配与异常处理

- 唯一键为 `(run_id, pipeline_id, source_file, lineno)`。检查重复键、缺失字段、非数值、布尔值、非有限值和负数；不将异常填零。
- 用 profile 入口、文件路径及源文本共同识别目标脚本，避免只凭 basename 错配；多个匹配项时报告歧义并停止该记录的语义分类。
- 规范化已知字符转义和换行后，将 profile 行文本与当前源码核对；保留原文与规范化文本，不进行泛化的破坏性转码。
- 每个 run 保留源码指纹。版本不一致时按源码版本分组；未匹配源码仍可展示原始热点，但不得按当前源码贴阶段标签。
- profile 中的其他文件、动态执行文件单列为 `external_or_dynamic`。未识别的脚本行列为 `unclassified`，都不能悄悄丢弃。
- 区分“明确记录为零”与“缺失/未报告”。不因缺失行而补零；跨轮统计显示实际有效次数。语义分组、占比和总量比较使用字段与源码验证通过的记录，并报告覆盖范围。

## 3. 阶段分类与统计设计

### 3.1 可审核的阶段映射

为每个候选生成逐行映射表：`pipeline_id, source_hash, lineno, source_text, stage, operation, mapping_reason`。结合源码 AST、调用对象和上下文生成初稿，再逐项审查有非零采样贡献的行；不能只用函数名关键词判定。

阶段固定为：

| 阶段 | 包含的操作 |
| --- | --- |
| imports | import / from import |
| input_validation | 文件读取、输入完整性和标签校验 |
| feature_engineering | 构造特征、字段转换、选择和切分数据 |
| preprocessing | imputation、encoding、scaling 的 fit/transform |
| model_fit | 分类器训练 |
| prediction | predict / predict_proba |
| blending_evaluation | 概率融合、阈值判定、评分 |
| output | 创建输出目录、写预测文件、输出日志 |
| orchestration | 初始化、控制流等可明确识别的其余逻辑 |
| unclassified | 无法可靠归类或单行混合多个阶段 |

`external_or_dynamic` 为文件范围分类，不强行归入上述业务阶段。包装调用按其可确认的主要操作标注，并注明不能分离其内部耗时；同一条语句不得被拆分后重复计数。循环头等采样位置按实际报告位置记录，不能凭推测搬到训练行。

### 3.2 逐轮汇总后再跨轮比较

- 长表保留各原始百分比字段、来源路径、源码状态、阶段、操作及映射理由。
- 先按 pipeline × run × stage 汇总，再统计阶段贡献的中位数、Q1、Q3、最小值、最大值及有效轮次数。
- “无该阶段”仅在源码确认该阶段不存在时记作结构性零；阶段存在但采样记录不完整时记作未知。
- 跨轮箱体只表示观测分散，不是置信区间。保留全部有效轮次，不删除离群点或默认剔除 run_01。
- 各阶段中位数不一定加总为原总量；总览堆叠图使用同一有效轮次集合的均值，误差分布另画，不把中位数强行堆成 100%。
- 行级热点按同一源码版本中的平均报告贡献排序，显示中位数、IQR、有效次数、正贡献轮数及进入每轮 Top 3 的次数。Top 3 仅对正贡献行排名，并列按文件路径、行号排序；不足三行则取实际数量。
- 分开报告“通常昂贵”“热点反复出现”“跨轮波动大”，不把出现频率当成实际函数调用频率。

### 3.3 可选 trace 只作为调用语义证据

检查 trace 格式和正整数调用计数，以 pipeline 与行号连接；没有源码指纹时明确标记 trace 与当前源码版本关系未验证。

trace 表示脚本行直接调用的库及次数，不覆盖库内部所有调用，且可能来自独立采集。不得复制成 10 轮观测、按调用次数分摊采样百分比或据此给出“某库耗时占比”。缺失 trace 不阻止 profile 主分析。

## 4. Cells 与图表安排

每个单元前说明输入、问题和方法，之后解释实际输出及边界。需要超过 30 行的读取或映射逻辑拆成小型、命名清楚的辅助函数 cells，并提供单独调用 cell。

| 单元 | 代码 cells | 输出与解读 |
| --- | --- | --- |
| 1. 目标与范围 | 无 | 明确本模块是采样热点归因，不是精确阶段计时 |
| 2. 前置与路径 | 检查 Module 1；显示输入与版本 | 前置变量、候选清单、字段定义说明 |
| 3. 原始结构检查 | 查看代表 profile；提取全部行记录 | 文件范围与字段可用性表，不打印海量原始 JSON |
| 4. 数据与源码校验 | 字段验证；源码规范化与匹配；覆盖汇总 | 问题表、源码版本表、有效轮次表 |
| 5. 阶段映射 | 构建映射；审查歧义和未分类行 | 可审核映射表与未分类贡献 |
| 6. 逐轮阶段表 | 阶段聚合；守恒核对 | 每个 pipeline/run 的阶段贡献与范围覆盖 |
| 7. 全候选概览 | 跨轮均值表；绘制图 1 | 按 Module 1 耗时排序的阶段堆叠横条图，保留外部与未分类部分 |
| 8. 重点候选 | 生成重点集合；阶段分布表；绘制图 2 | 分面点区间图：阶段中位数、IQR，以及全部轮次观测 |
| 9. 执行类型 | Python/native/system 分量表；绘制图 3 | 重点候选的报告分量图；不能直接推出 CPU 饱和或 I/O 阻塞 |
| 10. 源码行热点 | 行统计；逐轮 Top 3 频次；绘制图 4 | 每个重点候选 Top 5 行表和跨轮热力图，附源码、阶段与有效次数 |

| 13. 导出与复现 | 导出表、图和指纹 | 产物清单与解读过期提示 |

四类图保存 PNG/SVG；分面可按候选分多页以保证可读性。所有占比注明是 profiler-reported percentage，热力图缺失值使用区别于零的颜色；不以 100% 强制截断超出范围的异常数据。字段语义验证不支持合并时，图 1/2/4 改为三个独立分量面板，保留原始口径。

## 5. 输出、结论与验收

输出目录：`results/spaceship_titanic_students/descriptive_statistics/runtime_attribution/`。

导出原始行长表、数据问题表、文件范围与版本表、阶段映射、逐轮阶段表、跨轮统计、重点候选集合、热点行及稳定性表、可选 trace 表和图像。保存 manifest、profiles、源码、trace（若使用）、映射和分析代码的指纹；任一相关输入或代码变化均提示解读需重审。

结论使用“Evidence → Investigation direction → Required validation”结构。例如，持续出现的训练热点支持检查模型训练和重复训练机会；导入热点支持检查进程初始化成本。这些仍需后续对照实验，不能宣称已经确定优化收益。不得仅根据 native 分量高推荐 GPU，也不得将 system 分量直接称为磁盘 I/O 时间。

验收：

- 干净 kernel 按顺序运行 Module 1、2，无隐藏状态、外部旧表或 profiler 重跑依赖。
- 当前输入应检查 250 份 profile；完整性与 Module 1 一致，阶段有效覆盖另行报告。
- 用手工可核算的小型记录验证逐行求和、阶段互斥、跨轮统计、Top 3 并列和未分类保留；验证没有将 functions 重复加入。
- 每个有效 profile 的阶段总和与纳入的原始行贡献一致；与文件级百分比只作语义明确后的核对，不擅自强制相等。
- 验证转义字符、源码版本不一致、动态文件、重复行、缺失字段、非有限值、零贡献及不完整轮次；不得把不可比记录合并或缺失填零。
- 验证 trace 缺失或损坏时主分析仍可运行，未验证版本的 trace 显示限制。
- 图表清晰，英文解读逐项与已执行结果一致；保留不确定性和后续验证需求，不把采样占比换成未经验证的精确墙钟时间。
